# Third-Party Data & Libraries

This document records the external data sources and open-source libraries the
application relies on, so licensing, attribution, and refresh behaviour stay
explicit.

## Skill taxonomy

The resume-to-skills feature (`backend/services/skills/`) normalizes free-text
skill mentions onto a canonical vocabulary. Two sources are used, in order of
preference:

1. **Lightcast Open Skills API** — active only when `LIGHTCAST_CLIENT_ID` and
   `LIGHTCAST_SECRET` are set in the environment. The full skill list is
   cached in MongoDB (`skill_taxonomy`) and refreshed weekly; a stale cache
   falls back to the shipped CSV until the next successful refresh.
2. **ESCO-shaped skill subset** — `backend/data/esco_skills_min.csv`, always
   available so matching works with no external keys.

### ESCO attribution

The bundled subset is a curated list of common technical, business, design,
and soft skills organized in the shape of **ESCO** (European Skills,
Competences and Occupations), the European Commission's open multilingual
taxonomy of skills.

- Publisher: European Commission
- Licence: Open licences used by the Commission for ESCO (creative
  Commons / Free use). See `https://ec.europa.eu/esco/` for the canonical
  source and its licensing terms.
- The shipped file is a **curated subset** (roughly the most common tech and
  professional skills) in ESCO row shape (`id, skill, category, aliases`),
  generated by `scripts/generate_esco_subset.py`. It is not a verbatim export
  of the full ESCO database; where a row mirrors an ESCO entry the
  attribution above applies.

Regenerate or extend the subset with:

```
python3 scripts/generate_esco_subset.py
```

## Open-source Python libraries (AGPL-safe selection)

Parsing and matching use libraries chosen to keep the backend permissively
licensed:

- `pdfplumber` — PDF text extraction (choosen over PyMuPDF, which is AGPL).
- `python-docx` — DOCX text extraction.
- `rapidfuzz` — fuzzy string matching (Python bindings; the C core is
  MPL-licensed).
- `cleanco` — company-name normalization (used by the alumni-at-company
  feature).

All are installed via `backend/requirements.txt`.
